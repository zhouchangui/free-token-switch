# TokensBuddy DESIGN.md

## 1. Visual Theme & Atmosphere（视觉主题与氛围）

TokensBuddy 是面向 AI 编码用户的本地 Token 控制台。视觉语言应像一张安静、可信、可操作的路由矩阵: 用户能看见 Provider、Token、分享通道和市场节点之间的关系，也能相信每条路径都有状态、边界和停止能力。

**关键特征:**

- 专业桌面控制台，而不是营销站、交易所或钱包。
- 路由矩阵作为品牌记忆点: 节点、路径、边界、状态。
- 高信息密度但低视觉噪音，真实产品界面优先。
- “流动”必须被表现为受控路径，不是自由扩散。

## 2. Color Palette & Roles（色彩与角色）

### 品牌色与强调色

- **Matrix Blue** (`#2563EB`): 主行动、当前 Provider、导航选中、焦点。
- **Route Cyan** (`#0891B2`): 路由路径、连接、导入链接、矩阵图形。
- **Health Emerald** (`#059669`): 健康、可用、分享运行中、成功。
- **Ledger Amber** (`#D97706`): 市场、价格、付款、待确认。
- **Buddy Coral** (`#E11D48`): 少量分享温度和社媒点缀。
- **Stop Red** (`#DC2626`): 停止、删除、失败、高风险。

### 表面与背景

- **页面背景 Light** (`#F8FAFC`): 浅色页面基础。
- **页面背景 Dark** (`#0B1120`): 官网 hero 或深色主题基础。
- **卡片背景 Light** (`#FFFFFF`): 内容卡片、面板、弹窗。
- **卡片背景 Dark** (`#111827`): 深色内容表面。
- **抬升表面 Light** (`#F1F5F9`): hover、侧栏、分组。
- **抬升表面 Dark** (`#1E293B`): 深色 hover、侧栏、分组。
- **边框 Light** (`#D8DEE8`): 默认分割线。
- **边框 Dark** (`#334155`): 深色分割线。

### 文字与状态

- **主文字 Light** (`#0F172A`): 标题、正文。
- **主文字 Dark** (`#F8FAFC`): 深色标题、正文。
- **次文字 Light** (`#64748B`): 描述、元数据。
- **次文字 Dark** (`#94A3B8`): 深色描述、元数据。
- **成功 / 警告 / 错误 / 信息**: 分别使用 Health Emerald、Ledger Amber、Stop Red、Matrix Blue。

### 使用规则

- 青色路径不能替代绿色成功。
- 琥珀色只在市场和付款上下文出现。
- 深色矩阵背景只用于 hero、品牌图或关键流程，不作为所有页面背景。
- 不使用黑金、K 线、币面、强霓虹。

## 3. Typography Rules（字体规则）

### 字体家族

- **主字体 / UI**: `-apple-system`, `BlinkMacSystemFont`, `"Segoe UI"`, `Roboto`, `"Helvetica Neue"`, `Arial`, `sans-serif`
- **等宽字体 / 技术内容**: `ui-monospace`, `SFMono-Regular`, `"SF Mono"`, `Consolas`, `"Liberation Mono"`, `Menlo`, `monospace`

### 字体层级

| 角色 | 字体 | 字号 | 字重 | 行高 | 字距 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 首屏展示标题 | 主字体 | 48-72px | 750-800 | 1.05 | 0 | 仅官网首屏 |
| 章节标题 | 主字体 | 28-40px | 700 | 1.15 | 0 | 网站主要区块 |
| 正文 | 主字体 | 15-17px | 400 | 1.6 | 0 | 官网正文 |
| 界面文字 | 主字体 | 13-14px | 500 | 1.4 | 0 | App UI、标签、按钮 |
| 注释 | 主字体 | 12px | 400 | 1.45 | 0 | 状态解释、风险提示 |
| 等宽正文 | 等宽字体 | 12-13px | 500 | 1.4 | 0 | endpoint、token 片段、订单号 |

### 原则

- 中文与中英混排默认 `letter-spacing: 0`。
- 不按视口宽度动态缩放字体；使用明确断点字号。
- App 内不使用 hero 级标题。
- 技术标识可以等宽，但长文案不要等宽。

## 4. Component Stylings（组件样式）

### 按钮

**主按钮**

- 背景: Matrix Blue。
- 文字: 白色。
- 内边距: `h-9 px-4` 或桌面紧凑等价。
- 圆角: 8px。
- 悬停: 稍暗蓝色，不加大阴影。
- 用途: 下载、保存、启动、确认。

**次按钮**

- 背景: transparent 或 surface。
- 文字: 主文字或 Matrix Blue。
- 描边: 1px border。
- 内边距: `h-9 px-3`。
- 圆角: 8px。
- 用途: 查看、复制、返回、打开文档。

**危险按钮**

- 背景: Stop Red 或透明红色描边。
- 文字: 白色或红色。
- 用途: 删除、停止分享、撤销发布。
- 高风险按钮必须配明确文案，不只用图标。

### 卡片与容器

- 背景: surface。
- 描边: 1px 中性边框。
- 圆角: 8px。
- 阴影: 默认少用；浮层才使用轻阴影。
- 用途: Provider、流程步骤、状态记录、市场 listing。
- 禁止卡片嵌套卡片；需要层级时用分隔线和表面明度。

### 导航

- App 顶部切换器保持紧凑胶囊，但圆角不超过 10px。
- 当前 App 使用白/深色表面 + 轻阴影 + 蓝色细节。
- 网站 nav 不做强玻璃拟态；使用清晰背景和边框。

### 徽标与状态

- 当前 Provider: 蓝色描边 + 小状态点。
- 分享运行中: 绿色状态点 + “运行中”文案。
- 连接中: 青色状态点 + 低速动效。
- 市场待确认: 琥珀描边 + 短说明。
- 失败: 红色状态 + 可操作恢复建议。

### 图片 / 图表 / 产品视觉

- 官网 hero 使用真实 App mockup + 路由矩阵叠层。
- 矩阵背景线 1px，透明度低。
- 重要文字由 HTML/SVG 排版，不交给图片生成。
- 图表和流程图必须表达“从哪里来、到哪里去、是否可停止”。

## 5. Layout Principles（布局原则）

### 间距系统

- 基础单位: 4px。
- 紧凑节奏: 4 / 8 / 12 / 16 / 24px。
- 营销页 / 网站节奏: 24 / 40 / 64 / 96px。

### 网格与容器

- 最大宽度: 官网正文 1120-1200px。
- 首屏: 桌面端左右或上下组合均可，但必须第一屏露出产品真实信号。
- 核心区块: 用全宽 band + 内部 constrained layout，不用浮动大卡片当页面 section。

### 留白原则

- App UI 优先扫描效率，不做过大留白。
- 官网可以更开阔，但下一屏内容需在首屏可见。
- 流程图周围留白服务理解，不做装饰。

### 圆角尺度

- 微型: 4px，用于小标签或代码块。
- 标准: 8px，用于按钮、输入框、卡片。
- 面板: 10-12px，用于截图容器和 modal。
- 胶囊: 999px，用于状态和通道标签。

## 6. Depth & Elevation（深度与层级）

| 层级 | 处理方式 | 用途 |
| --- | --- | --- |
| 平面 | 背景 + 分区线 | 页面基础 |
| 表面 | 1px border + surface | 卡片、列表项 |
| 面板 | 较亮/较暗 surface + 轻阴影 | 弹窗、设置面板 |
| 浮层 | 明确阴影 + popover border | 下拉、tooltip、popover |
| 焦点 | Matrix Blue ring | 键盘焦点和关键选中 |

**深度原则:** 层级主要靠背景明度、边框和状态色，不靠厚重阴影。路由矩阵图形不应压过真实 UI 信息。

## 7. Do's and Don'ts（应该与不应该）

### 应该

- 用节点、路径和边界表达可控流动。
- 让 App 内状态清楚: 当前、健康、连接、分享、市场、错误。
- 保留桌面工具的信息密度。
- 在官网和 README 展示真实产品面板。
- 为深浅色主题分别检查对比度。

### 不应该

- 不做交易所、钱包、币圈、黑金或 K 线风格。
- 不把市场放在品牌视觉中心。
- 不铺满霓虹网格或大面积渐变。
- 不在产品 UI 内硬编码新的用户文案，工程落地需走 i18n。
- 不让路径线遮挡文字、按钮、Token 片段或价格。

## 8. Responsive Behavior（响应式行为）

### 断点

| 名称 | 宽度 | 关键变化 |
| --- | --- | --- |
| 移动端 | <640px | hero 改为纵向；路由矩阵折叠成步骤路径；按钮换行 |
| 平板 | 640-900px | 双列减少为单列或 1.5 列；截图缩小 |
| 桌面端 | 900-1280px | 完整 hero 和功能网格 |
| 大屏桌面 | >1280px | 增加矩阵边界空间，不无限放大字号 |

### 折叠策略

- 桌面矩阵: Provider 节点横向分布。
- 移动矩阵: 本地控制台 -> 分享/市场 -> 使用者，纵向路径。
- App 工具栏: 长标签可折叠为 icon + tooltip。

### 可访问性

- 所有 icon-only 控件需要 aria-label 或 tooltip。
- 状态不能只靠颜色表达，必须有文字或图标。
- 路径动效必须支持 reduced motion。
- 文本不使用 viewport-based font-size。

## 9. Agent Prompt Guide（Agent 提示词指南）

### 快速色彩参考

- 主行动: `#2563EB`
- 页面背景: `#F8FAFC` / `#0B1120`
- 卡片背景: `#FFFFFF` / `#111827`
- 主文字: `#0F172A` / `#F8FAFC`
- 次文字: `#64748B` / `#94A3B8`
- 默认边框: `#D8DEE8` / `#334155`

### 组件提示词示例

- “创建一个符合 TokensBuddy 路由矩阵视觉系统的官网首屏: 真实桌面 App 面板，节点和受控路径叠层，主标语为‘让闲置 Token 流动起来’，避免交易所、钱包、霓虹赛博。”
- “设计一个 Provider 卡片: 8px 圆角、1px 边框、当前状态使用 Matrix Blue，健康状态使用 Health Emerald，包含模型、endpoint、用量和分享入口。”
- “设计一个市场发布流程区块: 用 Ledger Amber 表示待确认步骤，但整体仍保持专业控制台风格，强调测试、发布、订单、停止。”

### 迭代检查指南

1. 先检查页面是否符合“本地 Token 控制台 + 受控流动”的产品前提。
2. 再检查颜色是否按角色使用，尤其市场色是否过度。
3. 检查路径和节点是否帮助理解状态，而不是装饰。
4. 检查移动端是否从矩阵改为可读步骤。
5. 检查是否出现币圈、钱包、交易所、AI 球体或乱码文字。
