## 方向 A: 控制中枢（Command Desk）

- 名称: 控制中枢（Command Desk）
- 核心隐喻: 一个高质量桌面工具的中控台，所有 Provider、Token、代理和分享状态都可以被看清、切换和回退。
- 目标感受:
  - 稳定、克制、可靠、接近 macOS / Windows 桌面生产力工具。
  - 用户第一眼相信“这里能管住复杂配置”。
- 适合场景:
  - 主 App UI。
  - Provider 列表、设置、用量、健康状态、故障转移。
  - 管理密集信息和日常高频操作。
- 不适合场景:
  - 需要强传播记忆点的官网首屏。
  - 需要解释“闲置 Token 流动”的品牌图形。
- 颜色倾向:
  - 中性浅色 / 深色表面。
  - 蓝色作为当前状态和主操作。
  - 绿色只用于健康和成功。
  - 橙色只用于市场和付款提醒。
- 字体倾向:
  - 系统 sans 作为主体。
  - 等宽字体只用于 endpoint、Token 片段、模型 ID、交易号。
- 形状语言:
  - 8px 圆角。
  - 1px 清晰边框。
  - 小面积状态高亮。
  - 不用大面积发光或装饰背景。
- Logo / icon 含义:
  - 可以使用控制台窗口、状态灯、切换节点作为辅助隐喻。
  - 单独做 icon 时容易缺少独特性，需要和路由路径结合。
- 社媒 / 官网含义:
  - 官网应展示真实产品界面和控制台状态，不适合只用抽象图。
  - README 图可以表现“多工具 Provider 一处管理”。
- 资产延展性:
  - App 组件最强。
  - 品牌图形中等。
  - 社媒传播中等。
- 专家推荐等级:
  - Brand Guardian: A-
  - UX Researcher: A
  - UI Designer: A
  - UX Architect: A
  - Visual Storyteller: B
- 最适合: 作为产品 UI 落地语言和组件系统基础。
- 风险:
  - 太像普通配置管理器。
  - “让闲置 Token 流动起来”的记忆点不够明显。

## 方向 B: 路由矩阵（Route Matrix）

- 名称: 路由矩阵（Route Matrix）
- 核心隐喻: Token 是被授权的资源包，在 Provider、工具、好友和市场之间沿着可见、可停止、可验证的路径流动。
- 目标感受:
  - 专业、技术、可控、有方向感。
  - 第一眼是开发者工具，不是交易所；第二眼能看见“流动”。
  - 像安静的网络路由台，而不是霓虹赛博屏幕。
- 适合场景:
  - App 总体视觉语言。
  - App icon / favicon / logo mark。
  - 官网首屏和 README 头图。
  - 分享通道、deeplink 导入、市场发布流程。
  - Provider 卡片激活态、代理接管态、健康状态。
- 不适合场景:
  - 需要大量财务数字、订单表格的页面，那里应转入“资源账本”子语言。
  - 高风险确认弹窗不应使用强流动动效，避免削弱严肃感。
- 颜色倾向:
  - 主底色仍保持中性色，优先浅色可读和深色沉稳。
  - 主色使用深湖蓝 / 控制台蓝，避免过亮消费级蓝。
  - 流动路径使用青蓝，但透明度低、面积小。
  - 成功和健康使用绿色。
  - 市场和付款只用少量琥珀。
  - 可加入少量冷灰、墨色、雾白，让系统看起来更像专业工具。
- 字体倾向:
  - App 内继续使用系统字体。
  - 标题使用更紧的字重层级，不夸张放大。
  - 等宽字体用于路由标签、token packet、状态码、端点和命令。
- 形状语言:
  - 节点: 小圆点、圆角方块、状态灯。
  - 路径: 细线、折线、轻微弧线，表现从本地到工具/好友/市场。
  - 矩阵: 轻网格、分区线、通道槽位。
  - 边界: 清楚分出本地、分享、市场三类区域。
  - 动效: 慢速、低透明度的路径流动；必须支持 reduced motion。
- Logo / icon 含义:
  - 主标记建议由 3-4 个节点和一条受控路径构成，暗示 Provider、Token、Buddy/Market 的连接。
  - 图形应像“路由/通道/切换”，不能像币种、钱包、星云或普通 AI 花瓣。
  - 小尺寸版本保留节点 + 路径的最小结构。
  - 单色版必须仍可识别为路径矩阵。
- 社媒 / 官网含义:
  - 官网首屏可以用真实 App 片段叠加路由矩阵，而不是抽象渐变。
  - README 头图可以表现“Claude / Codex / Gemini / OpenCode / OpenClaw / Hermes -> 受控 Token 通道 -> 分享 / 市场”。
  - 社媒卡片标题使用主标语，图形显示受控路径，避免价格和赚钱暗示。
- 资产延展性:
  - App icon: 强。
  - 横版 logo: 强。
  - favicon: 中强，需要专门小尺寸化。
  - 官网 hero: 强。
  - 产品 UI token: 强。
  - 社媒卡片: 强。
  - 市场页面: 中，需要配合资源账本子语言。
- 专家推荐等级:
  - Brand Guardian: A
  - UX Researcher: A-
  - UI Designer: A-
  - UX Architect: A
  - Visual Storyteller: A
  - Image Prompt Engineer: B+，更推荐 SVG / HTML/CSS 控制图形，不建议用纯 AI 生成重要 UI 或 logo。
- 最适合: 作为新版主品牌系统。
- 风险:
  - 网格、深色和发光一旦过量，会变成赛博风。
  - 路由隐喻如果只剩装饰线，会削弱可信度。
  - 需要在视觉系统阶段严格定义路径、节点、状态颜色和动效边界。

## 方向 C: 资源账本（Resource Ledger）

- 名称: 资源账本（Resource Ledger）
- 核心隐喻: 每个 Token、额度、价格、连接和订单都像可追踪的资源记录，用户知道资源从哪里来、去了哪里、是否完成。
- 目标感受:
  - 清楚、可靠、可审计、低情绪。
  - 像轻量资源管理系统，不像交易大厅。
- 适合场景:
  - 市场、订单、用量、价格、结算。
  - 分享运行日志、连接数、使用量、付款确认。
  - 卖家发布流程。
- 不适合场景:
  - 全局品牌第一眼。
  - App icon 或主 logo。
  - 需要表达“流动”和“连接”的品牌图。
- 颜色倾向:
  - 中性色为主。
  - 蓝色用于主操作。
  - 绿色用于可用和完成。
  - 琥珀用于价格、付款和等待确认。
  - 避免金色、黑金、收益曲线。
- 字体倾向:
  - 数字、价格、订单号可用等宽字体。
  - 文案短而具体，减少营销词。
- 形状语言:
  - 表格、列表、行项目、账本条目、状态徽标。
  - 少装饰，多边界和分组。
- Logo / icon 含义:
  - 不建议作为主 logo。
  - 可以成为市场页、订单状态或用量模块的子图标语言。
- 社媒 / 官网含义:
  - 适合解释市场流程和透明度。
  - 不适合做品牌头图。
- 资产延展性:
  - 市场和用量模块强。
  - 品牌系统弱。
- 专家推荐等级:
  - Brand Guardian: B+
  - UX Researcher: A-
  - UI Designer: A-
  - UX Architect: A-
  - Visual Storyteller: B-
- 最适合: 作为市场、订单、用量的子系统语言。
- 风险:
  - 过度使用会让产品像财务后台。
  - 容易压低“搭子”和流动叙事的温度。

## 推荐与决策

- 推荐方向: 路由矩阵（Route Matrix）
- 理由:
  - 它最能同时满足“专业桌面控制台”和“让闲置 Token 流动起来”。
  - 它把流动限定在可见、可控、可停止的路径里，能降低交易/投机误读。
  - 它能延展到 logo、App icon、官网首屏、README 图、分享通道和市场发布流程。
  - 它比控制中枢更有品牌记忆点，比资源账本更适合做第一印象。
- 用户已选择:
  - 路由矩阵（Route Matrix）。
- 用户拒绝的方向:
  - 控制中枢作为主视觉。
  - 资源账本作为主视觉。
- 拒绝原因:
  - 控制中枢稳但记忆点不足。
  - 资源账本适合市场子模块，但不适合作为整体品牌。
- 保留的备选元素:
  - 从控制中枢保留: 高密度真实桌面 UI、浅深色双主题、克制组件、清晰状态。
  - 从资源账本保留: 市场、订单、用量、价格相关的透明记录感。
- 待确认问题:
  - 新版 logo / app icon 是否完全重画，还是从现有图标里保留“多源流动”的一点基因。
  - 官网首屏是否优先展示真实 App 截图 + 路由矩阵叠层。
  - 市场模块的颜色和入口是否需要降噪，让它成为专业控制台中的受控流程，而不是橙色强入口。

## 专家评估摘要

## Brand Guardian 评审

- 一致性判断: 路由矩阵能把主标语里的“流动”约束成可信路径，和“专业桌面控制台”不冲突。
- 差异化判断: 相比一般 Token manager，路由矩阵能表达分享和市场能力；相比 marketplace，它保留本地控制和开发者工具感。
- 风险: 视觉不能像区块链网络、交易所或赛博地图。
- 建议修改: 视觉系统阶段要明确“路径颜色不是金钱颜色”，市场只作为一个节点，不是中心。
- 是否建议进入下一阶段: 是。

## UX Researcher 评审

- 首要用户判断: 用户最需要理解当前资源状态和分享边界，路由矩阵能帮助建立心智模型。
- 关键使用场景: 当前 Provider、代理接管、好友分享、市场发布、共享导入。
- 信任障碍: 如果路径没有状态说明，会变成漂亮装饰，无法增加信任。
- 可能误解: 深色矩阵和发光线可能被误读为黑客/赛博工具。
- 建议修改: App UI 内路径只在关键状态出现，默认界面保持安静。

## UI Designer 评审

- 界面适配判断: 可落地，但需要把路由矩阵做成 token 和组件规则，而不是每个页面都画网格。
- 组件与状态建议: Provider 卡片、分享胶囊、市场发布步骤、健康徽标可以共用节点/路径语言。
- 多尺寸风险: favicon 和 16px icon 必须简化到 2-3 个节点和一条路径。
- 可访问性风险: 青蓝路径在深色背景上容易过亮，在浅色背景上容易过淡，需要定义双主题色值。
- 建议修改: 阶段 3 需要给出色彩角色和状态用法，不允许用“漂亮蓝绿渐变”泛化。

## UX Architect 评审

- 信息架构判断: 官网应先讲控制台，再讲流动，不要把市场放在第一位。
- 布局与响应式建议: 桌面端可展示完整路由矩阵，移动端改为纵向路径和步骤。
- 工程落地风险: 需要为 Tailwind token、CSS 变量、组件状态和 landing page hero 提供具体规则。
- DESIGN.md 补充建议: 必须写清楚视觉主题、颜色角色、组件、布局、Do/Don't 和响应式行为。
- 替换清单建议: App icon、favicon、landing-page logo、README 头图、OG image、Provider 分享/市场模块状态。

## Visual Storyteller 评审

- 核心叙事: 闲置 Token 从孤立配置进入受控路径，被需要的人或工具重新使用。
- 视觉隐喻: 节点、路由、边界、路径状态、token packet。
- 传播记忆点: “Token 只沿你允许的路径流动”可以成为解释主标语的辅助句。
- 延展场景: Logo、官网首屏、社媒卡片、分享流程图、市场发布图。
- 风险与修改建议: 不要让路径像金融流动性图或区块链链路图。

## Image Prompt Engineer 评审

- 推荐生成方法:
  - Logo / icon: SVG 编程优先。
  - 官网 hero / README 头图: HTML/CSS 或 SVG 生成优先，可后期导出 PNG。
  - 抽象背景纹理: 如需可用 AI 生成，但不生成文字和真实 UI。
- Prompt 核心结构:
  - 专业桌面控制台、低干扰矩阵、可控 Token 路由、清晰节点、克制光线、中性表面。
- 负面约束:
  - 不要金币、K 线、钱包、区块链币面、霓虹赛博、乱码文字、假 UI 文案。
- 尺寸 / 格式建议:
  - 品牌图形使用矢量母版。
  - 社媒和 README 图使用 2x PNG 导出。
- 生成后 QA:
  - 检查小尺寸可读性。
  - 检查是否像交易所或币圈项目。
  - 检查文案是否由可控排版生成。
