## 方向 A: 流动控制台（Flow Console）

- 方向名称: 流动控制台（Flow Console）
- 目标感受:
  - 专业、可信、克制、开发者友好。
  - 像一个能看清 Token 状态、流向和边界的本地控制台。
- 适合的目标类型:
  - App: 非常强
  - Tool: 非常强
  - Developer product: 强
  - Website: 强
- 颜色倾向:
  - 保留当前蓝色作为信任感和激活状态基础。
  - 增加青色/翠绿色作为“流动健康 / 分享通道已激活”的强调色。
  - 使用灰色和 zinc 中性表面承载密集工具界面。
  - 避免橙色或钱币感成为主导；暖色只用于市场、付款警告或价格强调。
- 字体倾向:
  - 界面使用系统字体，保持清晰和平台一致性。
  - 等宽字体只用于 endpoint、Token 片段、路由标签和技术元数据。
  - 层级紧凑，不在 app 内使用过大的营销标题。
- 形状与布局倾向:
  - 密集但平静的仪表盘。
  - 8-12px 圆角、克制阴影、清楚边框。
  - 可使用流线、状态标签、路由图、Provider 节点、“从本地到分享”的进度步骤。
  - App 布局优先服务工具效率: 列表、面板、标签页、卡片、侧边控制。
- Logo / icon 含义:
  - 正向方向: 抽象路由/流动标记、Token 节点、切换箭头、循环连续性。
  - 可以把当前多彩径向图标作为种子，但应简化为更可识别、更可拥有的“流动控制”符号。
  - Icon 应被读成“Token 路由和流动”，不能像加密货币币种。
- 社媒卡片含义:
  - 使用深色或中性工作台背景，展示从本地 Provider 节点流向分享/市场端点的路径。
  - 文案可突出“让闲置的 Token 流动起来”。
  - 配合产品 UI 片段或路由图时，对开发者受众最有效。
- 官网含义:
  - 首屏应展示真实产品能力: Provider 切换、分享通道、市场发布流程。
  - 视觉隐喻: 本地控制面板 + 克制发光的 Token 流动路径。
  - 避免通用 AI 抽象渐变。
- 专家适配评估:
  - Brand Guardian: 最有利于建立信任和长期品牌资产，能避免被误读成交易平台。
  - UI Designer: 最贴合现有 Tailwind / shadcn-like 应用架构。
  - UX Architect: 最容易转化为设计 token、应用布局和官网 `design.md`。
  - Visual Storyteller: 叙事清楚，从本地 Token 控制走向受控流动。
  - Image Prompt Engineer: 后续如生成首屏图像，应使用干净的技术产品可视化，而不是人物生活方式照片。
- 风险与不适合场景:
  - 如果流动隐喻太弱，可能显得过于功能化。
  - 需要少量 “Buddy/搭子” 的温度，否则品牌可能像单纯配置工具。
  - 如果希望做高调增长型市场品牌，这条方向不够张扬。

## 方向 B: 搭子网络（Buddy Network）

- 方向名称: 搭子网络（Buddy Network）
- 目标感受:
  - 可信协作、轻社区感、资源互助。
  - Token 不只是 Key，而是在熟人、团队和市场之间有边界地流动。
- 适合的目标类型:
  - App: 中
  - Tool: 强
  - Developer product: 中
  - Website: 非常强
  - 社媒卡片: 非常强
- 颜色倾向:
  - 蓝色仍作为信任基础。
  - 用柔和琥珀色或珊瑚色表达“人和分享”的温度，但只作次级强调。
  - 用翠绿色表达成功分享通道和已验证可用状态。
  - 深色模式保持精致，只在连接路径周围使用柔和光感。
- 字体倾向:
  - 界面仍使用系统字体。
  - 官网和营销页面可以稍微更温暖、更口语。
  - 中文文案可以在标题、空状态中使用“搭子”；英文文案保持直接、专业。
- 形状与布局倾向:
  - 网络节点、搭子连接、邀请胶囊、分享卡片、权限路径。
  - 更强调人能理解的状态: “已分享给谁”“何时停止”“通道是否健康”。
  - 避免头像过多导致像社交产品；它仍然是开发者工具。
- Logo / icon 含义:
  - 正向方向: 两个或多个 Token 节点由受控路径连接，或暗示“从我到你”的流动标记。
  - 可以轻微表达搭子关系，但不能变成重吉祥物。
- 社媒卡片含义:
  - 很适合解释好友分享和团队使用。
  - 卡片可以用前后对比叙事: “不要裸发 Key -> 发一个受控分享通道。”
  - 如果后续做公众号/小红书风格内容，这条方向很适合。
- 官网含义:
  - 首屏可平衡产品截图与网络流动示意。
  - 页面章节应解释: 自用切换、好友分享、市场交易。
  - 如果希望用户记住“Token 搭子”，这条方向更强。
- 专家适配评估:
  - Brand Guardian: 更有记忆点，但涉及 Token 和安全时必须避免显得太随意。
  - UI Designer: 适合空状态、引导、分享弹窗和社媒卡片。
  - UX Architect: 需要清楚设计权限、停止分享和通道状态，否则会造成信任困惑。
  - Visual Storyteller: 比方向 A 更有情绪，因为它围绕“需要的人”展开。
  - Image Prompt Engineer: 后续图像应使用抽象产品网络可视化，不建议用人物素材。
- 风险与不适合场景:
  - 容易过度可爱或过度社区化。
  - 可能弱化 cc-switch 式的本地控制基础。
  - 绝不能暗示无边界公开分享。

## 方向 C: Token 流通轨道（Token Exchange Rail）

- 方向名称: Token 流通轨道（Token Exchange Rail）
- 目标感受:
  - 高效、清晰、有交易能力，但仍然受控。
  - 像一条从本地切换到好友分享再到市场交易的可追踪轨道。
- 适合的目标类型:
  - App: 中
  - Tool: 强
  - Developer product: 强
  - Website: 强
  - 市场/卖家页面: 非常强
- 颜色倾向:
  - 蓝色/靛蓝表达技术可信。
  - 翠绿色表达流动性和可用资源。
  - 琥珀色只用于价格、付款或结算强调。
  - 避免加密货币交易所常见的黑金、K 线色彩、钱币图形和激进渐变。
- 字体倾向:
  - 更偏数据产品: 紧凑标签、数字层级、状态徽标。
  - 等宽字体可更多用于交易号、订单号、资源标识。
- 形状与布局倾向:
  - 线性轨道、阶段管线、路由检查点、类账本卡片。
  - 适合卖家流程: 配置 -> 测试 -> 发布 -> 下单 -> 结算。
  - 明确划分边界: 本地、分享、市场、交易。
- Logo / icon 含义:
  - 正向方向: 轨道、分岔、切换节点、穿过检查点的 Token packet。
  - 不应像货币兑换或交易所 logo。
- 社媒卡片含义:
  - 适合商业化、市场发布和卖家说明。
  - 卡片可以表现“Token 从闲置到成交”的路径，但语言要克制。
- 官网含义:
  - 很适合市场页和卖家页。
  - 首页仍需先介绍切换/管理底座，否则会显得只是 marketplace。
- 专家适配评估:
  - Brand Guardian: 商业价值清楚，但最容易被误读成金融或交易所。
  - UI Designer: 很适合市场面板、发布流程、交易状态。
  - UX Architect: 需要强信息架构，把配置、分享、交易分清楚。
  - Visual Storyteller: 起承转合很清晰: 闲置 -> 测试 -> 分享/交易 -> 被使用。
  - Image Prompt Engineer: 后续生成应使用示意性轨道和流动图形，不使用钱币图像。
- 风险与不适合场景:
  - 如果视觉像加密货币、交易、快速赚钱产品，会带来最高的合规和信任风险。
  - 对主要关心切换和工具稳定性的 cc-switch 老用户不够友好。
  - 不建议作为全局品牌方向，除非市场/交易是最主要增长策略。

## 推荐

- 推荐方向: 方向 A 为主，选择性吸收方向 B。
- 理由:
  - TokensBuddy 需要保留 cc-switch 式的信任感和本地控制，同时引入分享与交易。
  - 方向 A 最适合作为 app 和开发者产品的基础系统。
  - 方向 B 可以在引导、分享流程、社媒卡片、空状态中加入“搭子”的温度。
  - 方向 C 更适合作为市场/卖家页面的子语言，不适合作为整体品牌身份。
- 建议组合:
  - 品牌基础: 流动控制台
  - 分享/引导时刻: 搭子网络
  - 市场与卖家流程: Token 流通轨道作为受控子语言
- 待确认问题:
  - App icon 是否要从当前多彩径向流动标记，演进为更简洁的“流动控制台”标记？
  - 官网首屏是否均衡表达“切换 + 分享 + 交易”，还是主打“让闲置的 Token 流动起来”？
  - 市场/交易在导航和视觉上是强入口，还是作为应用内部的受控流程？

## 方向对比

| 方向 | 最擅长 | 最弱项 | 推荐角色 |
| --- | --- | --- | --- |
| 流动控制台 | 信任、App UI、开发者工具、长期系统 | 情绪记忆点 | 主品牌系统 |
| 搭子网络 | 分享、社区、人的温度、社媒内容 | 严肃安全/交易感 | 次级表达层 |
| Token 流通轨道 | 市场、卖家流程、交易清晰度 | 过度使用会伤害品牌信任 | 市场子系统 |
